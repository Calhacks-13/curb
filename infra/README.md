# Curb Azure deployment

This directory provisions the demo's Azure Container Registry, serverless Cosmos DB account and containers, Web PubSub hub `curb`, Container Apps environment, managed image-pull identity, and two always-warm Container Apps.

The API and payment services each run with `minReplicas: 1`. This is intentional for the demo latency targets and incurs Azure charges until the resources are removed or scaled down.

## Prerequisites

- An Azure subscription with permission to create resource groups, role assignments, ACR, Cosmos DB, Web PubSub, and Container Apps.
- Azure CLI with Bicep and the Container Apps command group available.
- Bash, Git, Python 3, and curl.
- The Task 9 payment workspace and Task 11 Agentverse route integrated before public smoke testing.
- Sponsor credentials exported in the shell. Do not place them in command-line arguments, commit them, or paste them into Bicep parameter files.

Authenticate and select the intended subscription before deployment:

```bash
az login
az account set --subscription '<subscription name or id>'
```

## Configuration

The deployment script requires these server-held values:

```text
ANTHROPIC_API_KEY
PAYMENT_SERVICE_TOKEN
AGENTVERSE_API_KEY
CDP_API_KEY_ID
CDP_API_KEY_SECRET
CDP_WALLET_SECRET
CDP_DRIVER_WALLET_ID
CDP_OWNER_WALLET_ADDRESS
X402_FACILITATOR_URL
BASE_SEPOLIA_RPC_URL
```

`CURB_API_SERVICE_TOKEN` is optional and defaults to `PAYMENT_SERVICE_TOKEN`; set it explicitly when the payment client and FastAPI use different variable names for the same shared service credential.

Optional deployment settings:

| Variable | Default | Purpose |
|---|---|---|
| `AZURE_RESOURCE_GROUP` | `curb-demo-rg` | Target resource group |
| `AZURE_LOCATION` | `westus2` | Azure region |
| `AZURE_DEPLOYMENT_NAME` | `curb-demo` | Repeatable ARM deployment name |
| `CURB_RESOURCE_PREFIX` | `curb-demo` | Resource-name prefix |
| `CURB_IMAGE_TAG` | current 12-character Git SHA | Immutable image tag |
| `CURB_CORS_ALLOWED_ORIGINS` | local Expo web origins | Comma-separated browser origins; native iOS does not need CORS |
| `CURB_DEPLOY_OUTPUT_FILE` | `infra/.env.deployment` | Non-secret deployment outputs |

The remaining root `.env.example` variables are resolved as follows:

- `EXPO_PUBLIC_API_BASE_URL`, `EXPO_PUBLIC_WEB_PUBSUB_HUB`, `AZURE_COSMOS_ENDPOINT`, `AZURE_COSMOS_DATABASE`, and `AZURE_COSMOS_CONTAINER` are generated into the non-secret output file.
- `EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN` remains a mobile-build input and is never sent to either container.
- `AZURE_WEB_PUBSUB_CONNECTION_STRING` is generated by Bicep and stored only as an API Container App secret.
- `PAYMENT_SERVICE_BASE_URL` and `CURB_API_BASE_URL` are derived from the Container App FQDNs.
- CDP, x402, Anthropic, Agentverse, payment-service, Cosmos-key, and RPC credentials are referenced through Container App secrets and are not emitted as deployment outputs.

## Deploy

From the repository root:

```bash
bash infra/scripts/deploy.sh
```

The script is safe to rerun. It performs two Bicep deployments: the first creates shared resources and ACR, then ACR Tasks build and push both images, and the second deploys the Container Apps at those immutable tags. The API image uses `server/` as its build context. The payment image uses the repository root because `@curb/payments` imports the private `@curb/contracts` workspace package; `payments/` alone cannot resolve that dependency.

On API startup, `server/app/azure/cosmos.py` idempotently upserts the Palace of Fine Arts demo spots and driveways described in `CHANGES.md`. The deployment finishes by running the public smoke suite against those seeds.

Only non-secret values are written to `infra/.env.deployment`. Copy the `EXPO_PUBLIC_*` values into the mobile build environment as needed.

## Validate without deploying

```bash
az bicep build --file infra/main.bicep
docker build --file server/Dockerfile --tag curb-api:test server
docker build --file payments/Dockerfile --tag curb-payments:test .
bash infra/tests/test_deploy.sh
```

The payment build context intentionally differs from the original plan command for the workspace reason above.

## Public smoke test

Set the two deployed URLs, then run:

```bash
export CURB_API_BASE_URL='https://<api-app>.<container-apps-domain>'
export PAYMENT_SERVICE_BASE_URL='https://<payments-app>.<container-apps-domain>'
bash infra/scripts/smoke.sh
```

Smoke fails unless both health routes pass, a driver session is issued, the Palace of Fine Arts zone and driveway are present, realtime negotiation returns `wss://`, and Agentverse returns at most three options. It never prints the driver token or server-held secrets.
