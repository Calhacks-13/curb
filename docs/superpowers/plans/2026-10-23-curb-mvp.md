# Curb Hackathon MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished iPhone demo in which a genuine street-camera observation becomes a fresh legal parking option, a driveway can be paid for with x402, and an Agentverse agent can query the same supply before Sunday morning.

**Architecture:** An Expo iOS development build sends sampled camera frames to an always-warm FastAPI service on Azure Container Apps. FastAPI owns parking rules, calibrated YOLO occupancy, Cosmos state, nearby search, and Agentverse; a separate TypeScript service owns CDP wallets and x402 settlement, while Azure Web PubSub pushes committed state to both phones.

**Tech Stack:** Expo SDK 58, React Native, TypeScript, Expo Router, Mapbox, Python 3.11+, FastAPI, OpenCV, Ultralytics YOLO, Anthropic SDK, Node.js/Express, CDP SDK, x402, Azure Container Apps, Cosmos DB, Web PubSub, Agentverse ACP.

**Spec:** `docs/superpowers/specs/2026-10-23-curb-mvp-design.md`

## Global Constraints

- Target iPhone only; do not add Android acceptance work.
- Use Expo SDK 58 and a development/preview build because `@rnmapbox/maps` contains native code; Expo Go is not the acceptance environment.
- Find always uses the device's current location and a fixed radius of `804.672` meters (0.5 miles).
- Camera sampling runs only while Find is focused and the app is foregrounded, at approximately two compressed 720p JPEG frames per second.
- Freshness boundaries are exactly: green through 90 seconds, yellow after 90 seconds through 180 seconds, gray after 180 seconds through 300 seconds, hidden after 300 seconds.
- All business-time evaluation uses the IANA zone `America/Los_Angeles`; all persisted timestamps are UTC ISO 8601 values.
- All GeoJSON coordinates use `[longitude, latitude]` order.
- A curb opening is visible only for a mapped stall with passing occupancy confidence and a previously validated rule that is legal now.
- Public curb parking is never described as guaranteed or reservable; a driveway becomes guaranteed only after payment confirms.
- Driveway state is `UNAVAILABLE | AVAILABLE | HELD | BOOKED`; a hold has no automatic timeout.
- Disable owner recovery while payment is `PROCESSING`; payment retries reuse the same booking intent and never create a second payment.
- Use Base Sepolia testnet USDC only. No mobile bundle may contain Anthropic, Azure, CDP, x402, or Agentverse secrets.
- Raw frames and sign crops are processed transiently and deleted after inference; do not place them in Cosmos, logs, or source control.
- The street event shown as live must be genuinely captured end to end. Any fixture or later walkthrough must be visibly labeled `Demo replay`.
- Required performance gates: marker at the second phone within 5 seconds, rule revalidation within 10 seconds, x402 booking within 15 seconds, committed realtime update within 2 seconds.
- Run Python commands from the repository root in an activated Python 3.11+ virtual environment populated from `server/requirements.txt` and `server/requirements-dev.txt`.
- The root npm workspace contains exactly `mobile`, `payments`, and `packages/contracts`; `agents` is not an npm workspace or an independently deployed service.

## Review Focus

- Duplicate or out-of-order Web PubSub events must never roll an entity back; Task 4 adds reducer and server tests for monotonically increasing `entity_version`.
- DST transitions and exact availability/freshness boundaries must use `America/Los_Angeles` consistently; Tasks 2, 5, and 8 add boundary tests.
- Repeated payment requests and a settled-chain/failed-Cosmos split must never charge twice; Task 9 adds idempotency and reconciliation tests.
- Denied permissions, dropped network, and backgrounding must stop uploads cleanly and leave an honest designed state; Task 7 adds lifecycle and failure tests.
- Malformed frames, low-quality detections, and invalid Claude JSON must not create a green marker or destroy a last validated rule; Tasks 5 and 6 add rejection and cache-preservation tests.

## Locked External Contracts

### HTTP routes

| Method and path | Request | Successful response |
|---|---|---|
| `POST /v1/demo/sessions` | `{ profile: "driver" | "owner" }` | `{ user, token }` |
| `GET /v1/parking/nearby?lat=&lng=&radius_m=804.672` | seeded bearer token | `{ generated_at, zones, spaces, driveways }` |
| `GET /v1/spaces/{space_id}` | bearer token | full space detail view |
| `POST /v1/realtime/negotiate` | bearer token | `{ url }` scoped to hub `curb` |
| `POST /v1/vision/frames` | multipart JPEG plus JSON metadata | `202 { frame_id, accepted }` |
| `PATCH /v1/driveways/{id}` | `{ expected_version, available, price_usdc, availability_start, availability_end }` | driveway view |
| `POST /v1/driveways/{id}/holds` | `{ expected_version }` | booking intent with `PENDING_PAYMENT` |
| `DELETE /v1/driveways/{id}/holds/{booking_id}` | empty | released driveway view |
| `POST /v1/driveways/{id}/recover` | `{ expected_version }` | owner-only release when no payment is processing |
| `POST /v1/bookings/{id}/payment-processing` | `{ expected_booking_version }` | processing booking view |
| `POST /v1/bookings/{id}/finalize` | `{ idempotency_key, transaction_hash, expected_booking_version }` | confirmed booking view |
| `POST /v1/bookings/{id}/payment-failed` | `{ code, retryable }` | pending-payment booking view |
| `GET /v1/bookings/{id}` | bearer token | booking and receipt view |
| `POST /v1/payments/{booking_id}/execute` | bearer token | payment/booking result from payment service |
| `GET /v1/x402/bookings/{booking_id}` | x402 handshake | protected booking receipt resource |
| `POST /v1/agent/parking/search` | `{ lat, lng, radius_m }` | at most three ranked parking options |

Every mutation that touches a driveway or booking rejects a stale `expected_version` with HTTP `409`. The payment service authenticates to FastAPI with a server-only token, not a demo-profile token.

### Realtime envelope

`RealtimeEvent` is a discriminated union with:

```ts
type RealtimeEvent = {
  type:
    | "space.opened" | "space.refreshed" | "space.occupied" | "space.expired"
    | "sign_rule.updated" | "driveway.updated" | "driveway.held"
    | "driveway.released" | "booking.confirmed" | "payment.failed";
  entity_id: string;
  entity_version: number;
  occurred_at: string;
  payload: Record<string, unknown>;
};
```

The mobile reducer applies an event only when `entity_version` is greater than the version currently held for `entity_id`.
